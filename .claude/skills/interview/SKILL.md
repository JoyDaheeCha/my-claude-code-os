# interview — 모호함을 실행 스펙으로

## 목적

이 메모 OS에서 AI가 뭔가 "동작"하기 직전, 요청이 모호하면 **헛다리를 짚는다**.
interview는 그 앞단에 서서 **결정적으로 빠진 것만** 물어 요청을 구체화한다.
핵심은 질문을 많이 하는 게 아니라 **언제 물을지 / 언제 그냥 통과시킬지**를 판단하는 것.

## 역할 분담 (이 OS의 원칙)

- **판단(=이 문서, LLM)**: 무엇이 모호한가 · 무엇을 물을까 · 스펙을 어떻게 조립할까
- **저장/렌더(=`_shared/interview.sh`, 스크립트)**: id 부여 · 타임스탬프 · append · 주입 렌더

절대 스펙 저장 형식을 즉흥적으로 만들지 말 것. 반드시 `interview.sh save`에 위임한다.

## 언제 발동하나 (두 진입점)

1. **직접**: 사용자가 `/interview <모호한 요청>` 을 부를 때.
2. **공용 게이트**: 다른 스킬(capture, plan 등)이 실행 전에 "이 요청 모호하지 않나?"를
   확인하려 이 절차를 참조할 때. → 이때는 조용히 gate만 돌리고, 통과하면 원래 스킬로 즉시 복귀.

## 절차 (3단계)

### 1) Gate — 두 가지를 **곱해서** 판단한다

흔한 실수: "질문을 몇 개 할까"부터 생각하는 것. 그건 틀렸다.
게이트는 **① 무엇이 불확실한가 × ② 틀리면 얼마나 비싼가** 를 곱해서 공격성을 정한다.
질문 수를 최소화하는 게 목표가 아니다 — **틀렸을 때 비싼 곳을 정확히 조지는 것**이 목표다.

**① 불확실한 결정적 슬롯 식별** (값이 바뀌면 결과물이 달라지는 것):

- **what** — 진짜 원하는 산출물이 무엇인가
- **scope** — 어디까지/어디는 제외인가
- **done** — 무엇을 보면 "됐다"고 할 수 있나 (완료 기준)
- **for-whom** — 누가 읽나/쓰나 (톤·깊이가 갈림)
- **constraint** — 마감·형식·길이·금지사항 등 고정 제약

**② 스테이크 측정 — 이 슬롯을 잘못 짚으면 얼마나 비싼가:**

| 스테이크 | 신호 | 태도 |
|---|---|---|
| **낮음** | 되돌리기 쉬움, 5분이면 다시 함, 산출물 작음 (메모 한 줄 등) | 가정하고 진행 — 단 **가정을 드러낸다**(아래) |
| **높음** | 되돌리기 어려움/비쌈, 외부로 나감(전송·게시), 대량 파일 수정, 하루치 작업 | 결정적 슬롯이 **채워진 것 같아도 한 번 더 조진다** |

**핵심 규칙 — 조용한 가정 금지 (silently-assume 폐지):**
맥락(CLAUDE.md, 최근 대화, `interview.sh render`)으로 추론한 값은 **조용히 넘어가지 않는다.**
대신 추론한 슬롯을 **한 곳에 모아 "가정 카드"로 드러내고 거부권을 준다:**

> "나는 이렇게 가정했어요 — for-whom=토스 채용담당, 형식=한국어 STAR. 아니면 지금 반박하세요."

이러면 질문 왕복은 안 늘리면서(가정은 묻는 게 아니라 통보+거부권), 헛다리는 막힌다.

**게이트 판정:**
- 불확실 슬롯이 없고 스테이크도 낮음 → **가정 카드만 보여주고 즉시 통과**.
- 추론 불가능한 결정적 슬롯이 있음 **또는** 스테이크가 높음 → 2)로.

### 2) Converge — 스테이크에 맞춰 **공격성을 조절**

낮은 스테이크와 높은 스테이크에서 질문 강도를 다르게 한다:

- **낮은 스테이크**: `AskUserQuestion` **최대 2개**. 결과를 실제로 바꾸는 갈림길만. 나머진 가정 카드로.
- **높은 스테이크**: **상한을 풀고**, 결정적 모호함이 **하나도 안 남을 때까지** 판다.
  되돌리기 힘든 작업은 "대충 맞음"으로 진행하지 않는다 — 여기가 조지는 게 맞는 구간이다.

공통:
- 각 질문은 **구체적 선택지**를 주고, **추천안을 first 옵션**으로 두고 라벨에 "(추천)".
- 사용자는 항상 자유 입력(Other)이 가능하니, 선택지는 흔한 갈림길만 커버하면 된다.
- **취향 디테일(결과를 안 바꾸는 것)은 스테이크가 높아도 묻지 않는다** — 그건 조지기가 아니라 소음이다.

### 3) Persist — 스펙 조립 후 바로 저장 (확인은 최소화)

1. 답변을 반영해 **구체화된 실행 스펙 한 덩어리**를 만든다. (모호했던 원문 → 명확한 지시)
2. 스펙을 **인라인으로 보여주고 곧바로 저장**한다. 별도 "이대로 진행?" 확인 질문은 던지지 않는다.
   (여기까지 왔으면 이미 필요한 만큼 물어 수렴한 상태 — 또 확인하면 과잉 왕복이다.)
   대신 발급된 `id`와 함께 **되돌리는 법**을 한 줄로 안내한다: `interview.sh delete <id>`.
   예외: **되돌리기 어렵거나 외부로 나가는 작업**(파일 대량 수정, 전송/게시 등)일 때만 진행 전 한 번 확인.
3. 저장은 스크립트에 위임(형식은 스크립트가 고정):

```bash
echo '{
  "raw":   "<원래 모호했던 요청>",
  "spec":  "<구체화된 실행 스펙 한 덩어리>",
  "slots": {"what":"...","done":"...","scope":"..."},
  "qa":    [{"q":"<물어본 것>","a":"<답>"}],
  "tags":  ["<발동시킨 스킬 or 도메인, 예: capture/plan/resume>"]
}' | .claude/skills/_shared/interview.sh save
```

`save`는 부여된 `id`(예 `iv-20260702-2130-ab`)를 출력한다. 이후 이 스펙대로 실제 작업을 진행하거나,
공용 게이트로 불린 경우 원래 스킬에 이 `spec`을 넘긴다.

## 다른 스킬이 이 게이트를 쓰는 계약 (공용)

capture/plan 같은 스킬은 실행 직전 이렇게 참조한다:

> "요청이 모호하면 interview의 Gate(1단계)를 먼저 돌려라. 통과하면 그대로 진행,
>  질문이 필요하면 2~3단계까지 수행해 `spec`을 확보한 뒤 그 `spec`으로 실행하라."

과거 구체화 이력이 필요하면 주입용으로 당겨 쓴다 (Lazy · Just-in-Time):

```bash
.claude/skills/_shared/interview.sh render 3   # 최근 3개 스펙을 프롬프트에 이어붙임
```

## 하지 말 것

- **조용한 가정** — 추론한 값을 티 없이 넘어가기. 반드시 "가정 카드"로 드러내고 거부권을 줄 것
- **스테이크와 무관하게 질문 수 고정** — 낮으면 가정으로 줄이고, 높으면 상한을 풀어라. "무조건 2~3개"도 "무조건 다 조지기"도 틀림
- 결과를 안 바꾸는 **취향 디테일** 묻기 (스테이크가 높아도 이건 소음)
- 스펙 저장 형식을 손으로 만들기 (반드시 `interview.sh save`)
